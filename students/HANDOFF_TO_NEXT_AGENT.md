## 4.1. Автозапуск после перезагрузки сервера (проверено)

При ребуте поднимаются **и новый стенд, и старый :4601**:

| Что | Как включается |
|-----|----------------|
| workspace (`/srv/opencode-student/workspace`) | строка в `/etc/fstab` (loop-ext4), systemd-юнит `srv-opencode\x2dstudent-workspace.mount` |
| Docker | `systemctl is-enabled docker` → `enabled` |
| 4 контейнера стенда | `restart: unless-stopped` → Docker поднимает их при старте демона |
| старый OpenCode `:4600` | user-сервис `opencode-web.service`, `enabled` |
| старый стенд `:4601` (Caddy) | user-сервис `caddy.service`, `enabled` |
| продление TLS | `opencode-student-cert.timer`, `enabled`, `Persistent=true` |
| восстановление датасетов | `opencode-student-restore.timer`, `enabled`, `Persistent=true` |
| пересборка каталога датасетов | `opencode-student-catalog.timer`, `enabled`, `Persistent=true` |
| user-сервисы без логина | `Linger=yes` у deployagent |

Нюансы:
- `unless-stopped` означает: если стенд **явно** остановить (`docker compose stop/down`)
  и перезагрузиться, контейнеры не поднимутся. В обычном состоянии — поднимутся.
- Docker стартует после `local-fs.target`, поэтому loop-раздел успевает смонтироваться
  до bind-mount в контейнеры.
- После ребута полезно проверить:
  `sg docker -c "docker compose ps"` и `sg docker -c "bash scripts/50-verify-isolation.sh"`.

## 6. Риски

1. **Docker DNS не работает под gVisor.** При смене сети/egress сохранить статический
   IP `172.28.0.254` у egress и `172.28.0.5` у edge, а также `extra_hosts` у
   sandbox, иначе песочница потеряет прокси и edge.
2. **TLS-файлы приватны:** `edge/letsencrypt/` и `edge/certs/privkey.pem`. Не коммитить
   и не публиковать. Если папку когда-нибудь добавят в git — внести в `.gitignore`.
3. **IP-сертификат короткоживущий (~6 дней).** Если таймер отключить, стенды «протухнут»
   за неделю. Проверка: `openssl x509 -enddate -noout -in edge/certs/fullchain.pem`.
4. **`envsubst` в edge** подставляет только экспортированные переменные.
5. **gVisor защищает от побега, не от действий агента** и не от prompt-injection.
6. Правки `config/opencode.json` и навыка применяются после `docker compose restart sandbox`.
7. **`agents.<name>.instructions` в V2 молча игнорируется** — только top-level
   `instructions` или `system`/Markdown-агент.
8. **`/files/` открыт без пароля.** Если это нежелательно — вернуть `auth_basic` в
   `edge/site.*.conf`. CSP `sandbox` у `/files/` обязателен: он не даёт HTML из песочницы
   выполняться в origin UI OpenCode. Не убирайте его, если сохраняете инлайновые скрипты.
9. **Наш `sw.js` — точка отказа.** Если OpenCode обновится и его штатный service worker
   вернётся, симптом «Unrecognised route!» вернётся. Лечится либо правкой
   deny-листа в его `sw.js`, либо возвратом `edge/sw.js` (он монтируется в контейнер,
   перезапуск edge делается без пересборки образа).
10. **Студент, у которого стенд был открыт до фикса service worker**, должен один
    раз перезагрузить страницу — тогда браузер поставит наш SW. Новые вкладки
    получают его сразу.
11. **Chromium в образе песочницы — тяжёлый пакет** (~660 МБ, образ 2.4 ГБ). Если
    образ мешает (например, мало места под `/var/lib/docker`), соберите без него:
    `docker compose build --build-arg WITH_BROWSER=false sandbox`. Тогда агент
    не сможет проверять страницу в браузере — и SKILL.md об этом надо помнить.
12. **Проверка service worker требует браузера с поддержкой SW** (`chromium-headless-shell`
    не умеет service worker'ы, обычный `chromium` умеет). На сервере оставлен
    тестовый образ `chrome-full:local` — пересобрать:
    `printf 'FROM alpine:3.24\nRUN apk add --no-cache chromium fontconfig ttf-dejavu\n' > /tmp/Dockerfile && docker build -t chrome-full:local /tmp`.
    A/B-тест делается так: подменить `edge/sw.js` на штатный (взять из
    `opencode/` образа или из кэша браузера), перезапустить edge, открыть в
    браузере страницу с `navigator.serviceWorker.register('/sw.js')` и
    переходом `location.href` на `/files/...` — при штатном SW запрос файла
    до сервера не доходит вовсе.

```
агент → cat /proc/self/environ → достаёт AI_GATEWAY_API_KEY
агент → python3 + urllib (curl/wget запрещены политикой, urllib — нет)
     → POST https://ai-gateway.vercel.sh/v1/chat/completions {"model":"openai/gpt-5-nano"}
     → HTTP 200   ← ПЛАТНАЯ МОДЕЛЬ, минуя и список моделей, и лимит
```

То есть список моделей в UI ограничивал только **честного** студента; ключ в песочнице
снимал ограничение целиком. Дополнительно: удаление записи из `credential` через API **не
стирает** ключ из файла БД — нужен `VACUUM`, иначе `grep` по `opencode.db` его находит
(в таблице строк уже 0, а в файле байты ещё лежат).

**Решение — вынести ключ из песочницы в отдельный контейнер-прокси:**

| Часть | Файл | Роль |
|-------|------|------|
| Прокси | `sandbox/gateway/proxy.py` (+ `Dockerfile`) | держит настоящий ключ, отдаёт наружу только модели из `ALLOWED_MODELS`; остальное — 403. Свой ключ в `Authorization` подставляет прокси, клиентский игнорирует |
| Сервис | `docker-compose.yml` → `gateway` | ключ из `.env` → `AI_GATEWAY_API_KEY`, белый список → `ALLOWED_MODELS`; uid 65534; сети `sandbox_net` (статический IP 172.28.0.253) + `egress_out` (интернет мимо allowlist песочницы) |
| Провайдер | `config/opencode.json` → `provider."vercel-free"` | свой список из 3 моделей, `baseURL: http://gateway:8080/v1`, `apiKey: "local-proxy"` (заглушка) |
| Политика | `config/opencode.json` → `policies` | `provider.use`: deny `*`, allow `opencode`, `opencode-go`, `vercel-free` — каталоговый `vercel` (315 моделей) скрыт |

Под gVisor Docker DNS не работает (правило 8), поэтому `gateway` получил статический IP и
запись в `extra_hosts` песочницы; в `NO_PROXY` добавлено `gateway` и его адрес, иначе
запрос к прокси пошёл бы через egress и там заблокировался бы.

**Проверено на живом стенде после переделки:**
- `/api/model` → 13 моделей (10 `opencode` + 3 `vercel-free`); каталогового `vercel` — 0;
- все три модели отвечают из контейнера;
- `cat /proc/self/environ | grep -c AI_GATEWAY` в песочнице → **0**; `grep -rlao "vck_..."` по
  всей ФС песочницы → пусто (после `VACUUM`);
- прямой запрос в шлюз из песочницы → 401 (ключа нет);
- платная модель через прокси → **403** с русским сообщением;
- `50-verify-isolation.sh` → **13/13**; баланс шлюза не изменился (14.7317 → 14.7317 — все три
  модели бесплатны).

**Списки должны совпадать** в двух местах: `config/opencode.json`
(`provider."vercel-free".models`) и `.env` (`GATEWAY_ALLOWED_MODELS`). Расхождение →
в UI модель есть, а прокси её режет (403).

### Д.1. Пароль Beszel

Живой пароль админа лежит в SQLite (`monitoring/data/data.db`), а `USER_PASSWORD`
из env работает только при самом первом старте, поэтому правкой `.env` пароль не
меняется. Через UI (Settings → Users) тоже не вышло: у коллекции `users` пустой
`updateRule` → PATCH обычным токеном даёт 403 «Only superusers can perform this
action», а `passwordConfirm` обязателен.

Сработал путь через PocketBase-суперюзера (он же админ Beszel):
`/api/collections/_superusers/auth-with-password` → PATCH
`users/records/{id}` и `_superusers/records/{id}` с `password` +
`passwordConfirm` (+`oldPassword`) → проверка входа старым и новым паролем →
обновление `monitoring/.env` → `docker compose up -d beszel` (пересоздание, чтобы
env разошёлся с БД).

Скрипт оставлен в `/srv/opencode-student/monitoring/change-password.py` (читает оба
`.env`, секреты не печатает). Старый пароль после смены не принимается (проверено
снаружи, порт 8090).

| № | Симптом | Причина | Правка |
|---|---------|---------|--------|
| 40 | «Пароль Beszel не меняется через UI» | У коллекции `users` пустой `updateRule`; PATCH токеном админа → 403 | Вход суперюзером PocketBase → PATCH обеих записей с `passwordConfirm`; готовый скрипт `monitoring/change-password.py` |

**Риск, о котором стоит помнить:** порт 8090 открыт наружу без TLS, а теперь
на панели стоит пароль, который знают студенты (он же стендовый). При смене
стендового пароля Beszel надо синхронизировать тем же скриптом.
