# Configurable one-page dashboard — draft v0.5

## Приоритеты

Требования пользователя и автономность → этот Skill.MD → дополнительный дизайн-скилл Hallmark.

Один HTML содержит данные, стили, JavaScript, иконки и полный текст этого скилла. Просмотр работает через file:// без интернета, CDN, внешних шрифтов и AI API. Предусмотренные изменения пользователь выполняет без агента, новые источники и формулы добавляет агент.

## 1. Подготовка и модель

Прочитай предоставленный файл, проверь разделитель, типы, пропуски, специальные значения и размер. Не удаляй и не обрезай строки молча. Строки не называй уникальными клиентами без ID.

Если вопрос уже согласован — не начинай анкету заново. Иначе предложи 2–3 вопроса и уточни фокус одним сообщением. Определи доступные инструменты среды, не предполагая чужих путей и установленных библиотек.

Dimension / измерение — по чему группируем. Measure / показатель — что считаем. Значение измерения — конкретная категория. Технические ID отделены от названий.

Разделяй DATA (строки), MODEL (метаданные и формулы), CONFIG (общие настройки и графики), STATE (фильтры, выбранный сегмент, панель). Поток: данные → единый отбор → KPI и группы → render.

Для небольшого файла допустимы все строки и расчёты в браузере. Для большого агрегируй заранее с сохранением необходимых разрезов и достаточных статистик. Не обещай переключения, для которых данные потеряны.

## 2. Дашборд и действия

На странице аналитический вопрос, 3–4 KPI, 3–4 связанных графика, до трёх общих фильтров и видимый текущий отбор.

Общие фильтры и клик по категории действуют на все блоки, включая график-источник. Повторный клик снимает выбор. Enter/Space повторяют клик; тултип доступен по наведению и фокусу. «Остальные» выбирает множество объединённых категорий.

В верхней панели только действия, которые нужны пользователю:
- иконка дискетки: сохранить HTML;
- шестерёнка: открыть общие настройки.

Не показывай плашку «Автономный режим» и текстовую кнопку «Сохранить HTML». Иконки имеют title и aria-label, а область нажатия — не меньше 44 px. Шестерёнка каждого графика сразу открывает его настройки.

## 3. Ровно два раздела настроек

Панель закрыта по умолчанию. Вкладки только «Общие» и «Графики». Escape закрывает панель. Отдельного редактора полей и формул нет.

Общие: заголовок, светлая/тёмная тема, общий цвет графиков, точность, подписи значений. JSON экспорт/импорт — в раскрываемом блоке «Конфигурация». Внизу — отмена и сброс оформления.

Графики: полный список, переключатель «Показывать график», заголовок или автоназвание, dimension, measure, совместимый тип, переключатель собственного цвета и сам цвет.

В раскрываемом «Дополнительно»: сортировка, Top N, локальная точность и подписи, возврат локальных overrides. Не показывай все технические параметры одновременно.

## 4. Видимость и наследование

У каждого графика visible: boolean, по умолчанию true. Скрытие убирает карточку, но не удаляет настройки и не меняет KPI, фильтры и данные. Скрытый остаётся в списке с пометкой «скрыт», доступной через общую шестерёнку. Видимость сохраняется в JSON и HTML и поддерживает отмену. Если скрыты все, покажи понятное сообщение и кнопку возврата к настройкам графиков.

Общие значения — defaults; локальные значения — только отличия. null означает наследование. Собственный цвет сохраняется при общей правке; выключение собственного цвета возвращает наследование. Сброс overrides не меняет видимость. Изменение вида не меняет вычисляемые показатели.

```json
{
  "version": 5,
  "global": {"theme": "light", "accent": "#14704e", "decimals": 1, "showLabels": true},
  "charts": [{
    "id": "segments", "visible": true,
    "dimension": "job", "measure": "rate", "type": "hbar",
    "overrides": {"color": null, "decimals": null, "showLabels": null}
  }]
}
```

## 5. Аналитическая корректность

Для категорий: горизонтальные/вертикальные столбцы и таблица. Линия доступна только для упорядоченных измерений в естественном порядке и без Top N. Несовместимый тип автоматически заменяется совместимым.

Доля = число положительных исходов / число строк текущей группы после всех фильтров. Среднее считается по имеющимся значениям, законные нули сохраняются. «Остальные» пересчитываются по объединённым исходным строкам, не суммой и не простым средним процентов. Нулевой знаменатель даёт отсутствие значения, не 0%.

Не обрезай отрицательные значения, покажи нулевую линию. Столбцы начинаются от нуля; шкала долей может быть 0–100%. Тултип содержит значение с единицей, n, положительные исходы и знаменатель. Малые группы отмечай как эвристику, не статистическую значимость. Не делай причинных выводов.

Пустая выборка — сообщение и сброс. База KPI подписана: вся исходная выборка не является предыдущим периодом.

## 6. Hallmark: дополнительное направление дизайна

Источник: https://github.com/Nutlope/hallmark . Прочитаны основной SKILL.md, flow.md (App screens) и redesign.md. Используется адаптация правил, а не заявление о полном выполнении штатного Hallmark CLI pipeline.

Экран — app screen: рабочий аналитический инструмент. Не превращай его в лендинг, не добавляй маркетинговый hero, отзывы, картинки-заглушки, scroll-reveal и выдуманные метрики.

Посмотри, какие темы подходят для аналитической панели по текущей задаче, и предложи
студенту выбор. В конструкторе (§10.9) уже есть четыре адаптированные темы —
almanac, console, coral, furrow: достаточно предложить 2–3 из них.

Применяй:
- все цвета и шрифты объявлены токенами :root или theme block;
- фиксированная типографическая шкала, табличные цифры, системный sans для app screen;
- без eyebrow над каждым заголовком, капительных разреженных подписей и декоративных status dots;
- без метастрок, соединённых средними точками, и стрелок, приклеенных к тексту ссылок;
- без карточек внутри карточек, градиентных заливок, эмодзи-иконок и фальшивых окон браузера;
- мгновенный focus-visible, reduced motion, только небольшие state-переходы;
- никакого transition: all и анимации ширины, высоты, top или left;
- ограниченный центрированный контейнер, minmax(0, 1fr), перенос длинных заголовков;
- яркие цифры остаются реальными данными, цвет не единственный носитель смысла;
- сохраняй всю аналитику и поведение предыдущей версии, кроме явно запрошенных изменений.

Управляемый общий цвет графиков не обязан перекрашивать всю декоративную палитру: пользователь настраивает данные, а не ломает контраст интерфейса. При необходимости меняется только --chart-color, локальное исключение имеет приоритет.

Осознанные приоритеты: автономный файл и этот skill выше правил внешнего набора. Фильтры сохраняются в экспортируемом HTML, а не обязаны жить в URL. Полный текст Skill.MD является документацией, для него допустим моноширинный шрифт. SVG-графики — реальные данные, не декоративные иллюстрации.

Если полный Hallmark доступен в OpenCode, можно дополнительно выполнить штатный sloplint --scope app --render и указать фактический результат. Если его нет, используй доступную браузерную проверку и не называй её прохождением sloplint или fresh-context review. Не выдумывай audit pass.

## 7. Автономность, источник и безопасность

Внизу раскрываемый блок «Skill.MD»: полный текст этой версии как plain text, с переносами, ограниченной прокруткой и скачиванием. Отдельный файл и встроенный текст должны совпадать.

Всё работает без внешних запросов. Системные шрифты разрешены; дополнительные файлы не загружаются. Иконки — inline SVG. При отключённом JavaScript явно объясни ограничение интерактива и покажи статическую справку по источнику, не оставляй совершенно пустую страницу.

JSON содержит CONFIG и версию. Валидируй размер, структуру, IDs, enum, диапазоны, совместимость, HEX-цвета и visible boolean. Создавай чистый объект по разрешённым ключам. Запрети __proto__, prototype, constructor. Не используй eval или произвольный deep merge.

Пользовательские строки экранируй, skill вставляй через textContent; символ < в JSON внутри script экранируй. Экспорт HTML сохраняет CONFIG, фильтры, клик-отбор, видимость и полный skill. Временные панели и тултипы не сохраняются. Автосохранения нет.

## 8. Учебные данные bank.csv

Вопрос: в каких сегментах выше наблюдаемая доля оформлений депозита и каков размер групп?

Показатели: число строк, число y = yes, доля y = yes, средний balance и средняя duration. KPI — первые четыре. Разрезы: job, education, contact, housing, marital, month и возрастные группы. Фильтры: education, contact, housing.

Нет ID клиента — строки не уникальные клиенты. Нет года — месяц не полноценный временной ряд. Balance — среднегодовой баланс в евро, не доход кампании. Duration известна после контакта. Различия не доказывают причинность.

## 9. Проверки и передача

Проверь в настоящем браузере при отключённой сети (на стенде это делают два готовых
скрипта — см. §10.3; собственный тестовый фреймворк писать не нужно):
- KPI и все группы против независимого расчёта;
- фильтры, клавиатуру, тултипы, пустую выборку, отрицательные значения;
- две вкладки, шестерёнки, отсутствие плашки режима и текстовой кнопки сохранения;
- дискетка скачивает HTML и имеет доступное имя;
- скрытие, восстановление, скрытие всех и отмену;
- наследование, смену типа, Top N и корректность «Остальных»;
- JSON round-trip с видимостью и отклонение невалидного импорта;
- повторное открытие HTML с сохранёнными настройками, видимостью, отбором и skill;
- узкие экраны, длинные заголовки, обе темы, reduced motion, контраст;
- отсутствие JS-ошибок и внешних запросов.

Не выдавай чтение кода за браузерный тест. Отдай HTML и Skill.MD реальным механизмом среды. Не выдумывай URL. Коротко опиши дизайн, изменения и фактически выполненные проверки.

## 10. Стендовые правила (обязательные)

Это дополнение к §1–9: конкретные пути и проверки этой песочницы. Противоречий нет —
здесь только то, чем правила выше выполняются на стенде.

### 10.0. Порядок действий (прочитать до начала работы)

1. `python3 /opt/tools/new_task.py` — своя папка задачи (§10.1), дальше работать в ней.
2. Собрать страницу готовым конструктором `/opt/viz/kit` (§10.9): он уже выполняет
   §2–§7 (две иконки, панель настроек, наследование, Top N, сохранение HTML,
   блок Skill.MD). Писать этот движок вручную не нужно.
3. Проверить: `check_page.py` и `kit/verify_page.py` — по одному прогону (§10.3).
4. Один скриншот и просмотр глазами: `python3 /opt/viz/screenshot.py …` (§10.3).
5. Отдать ссылку (§10.2) и коротко объяснить, что получилось.

### 10.1. Своя папка на каждую задачу

Все студенты работают в одной общей папке `/work`, поэтому писать в общие
`output/` и корень `/work` нельзя — работы перезапишут друг друга.

Первым действием каждой задачи создай свою папку:

```sh
python3 /opt/tools/new_task.py
# → /work/sessions/task-20261027-160512-a1b2
```

Дальше **всё** делай внутри неё (`$TASK` = напечатанный путь):

- скрипты и промежуточные файлы — `$TASK/*.py`, `$TASK/*.csv`;
- результат — `$TASK/output/<имя>.html`;
- скриншот — `$TASK/preview.png`.

Папку создавай один раз за задачу и переиспользуй в диалоге. Чужие папки в
`/work/sessions/` не читай и не меняй.

**Рабочий каталог команды — папка задачи, а не `/work/data`.** Данные читай по
полному пути, запуская из своей папки:

```sh
cd "$TASK" && python3 -c "
import pandas as pd
df = pd.read_csv('/work/data/bankloan_cs.csv')
print(df.shape)
"
```

`/work/data` доступен **только для чтения** (права 555/444): запись туда
завершится `Permission denied` — так и задумано, ничего не пересоздавай в обход.
Всё, что нужно сохранить, пиши в `$TASK/output/` или рядом в `$TASK/`.

### 10.2. Ссылка на результат

```
https://<адрес стенда>/files/sessions/<id>/output/<файл>.html
```

Адрес стенда — в переменной окружения `PUBLIC_URL`. Ссылку отдавай только
после зелёной проверки из 10.3. Без `/files/` ссылка попадёт в UI OpenCode и
покажет «Unrecognised route!».

### 10.3. Проверка в браузере — до выдачи ссылки

```sh
python3 /opt/viz/check_page.py "$TASK/output/page.html"       # ошибки JS, внешние запросы
python3 /opt/viz/kit/verify_page.py "$TASK/output/page.html"  # фильтры, отбор, темы, импорт
python3 /opt/viz/screenshot.py "$TASK/output/page.html" --out "$TASK/preview.png"
```

Достаточно **одного** прогона каждой команды и **одного** скриншота, который
ты смотришь глазами. Пути можно указывать от текущей папки задачи —
`output/page.html` работает.

`check_page.py` должен быть зелёным (`✓ Ошибок нет`). Если он ругается —
исправь и прогони снова. `console.log` проверку больше не валит: в отчёте он
идёт отдельным списком «Сообщений console.log». Если проверка висит дольше
25 секунд, скрипт сам скажет, что случилось (обычно — Chart.js и
`responsive: true`, см. §10.11).

`verify_page.py` проверяет интерактив универсально: фильтры сужают выборку,
клик по категории даёт отбор, повторный клик его снимает, скрытие графика
убирает карточку, тёмная тема включается, невалидный JSON отклоняется. Свой
тестовый скрипт с многократным запуском браузера писать не нужно — это уже
сделано.

Чтение кода тестом не считается. `sloplint` в песочнице нет (нет node) — не
называй проверку его именем.

### 10.4. Жёсткие лимиты

База — 3–4 графика из §2. Потолок на одну страницу: **не больше 6 графиков,
не больше 3 фильтров, не больше 1 дополнительного показателя, не больше
100 000 строк** в браузере. Если данных заметно больше — агрегируй заранее и
скажи, что именно свернул. Скажи студенту эти рамки до начала работы.

### 10.9. Конструктор дашборда `/opt/viz/kit` (основной путь)

Движок страницы уже написан и протестирован: §2–§7 выполняются им, а не тобой.
Полное описание — `/opt/viz/kit/README.md` (прочитай один раз в начале задачи
через `cat`). Типовая задача по World Bank собирается одной командой:

```sh
cd "$TASK"
python3 /opt/viz/kit/examples/wb_country.py \
    --csv wb_gini.csv \
    --title "Неравенство по странам: индекс Джини" \
    --question "В каких странах неравенство выше и как оно менялось в 2015–2023?" \
    --out output/dashboard.html
```

`examples/wb_country.py` — шаблон: скопируй в `$TASK`, поменяй `--csv`, подписи
и графики. `examples/bank_share.py` — второй случай (доля `share` со
знаменателем в тултипе). Свой вариант задачи собирается через `spec.json`:

```sh
python3 /opt/viz/kit/dashboard.py --spec spec.json --out output/dashboard.html
```

Что описывается в `spec.json` (подробности и все поля — в README):
- `dimensions` — по чему группируем, `measures` — что считаем
  (`mean/sum/min/max/median/first/last/count/count_distinct/share`);
- `kpis` — 3–4 значения, считаются по текущему отбору;
- `filters` — до трёх, `default: "last"` = максимальное значение в колонке;
- `charts` — до шести: `hbar`, `vbar`, `line` (только `ordered`-измерение),
  `table`; `topN` + `rest` сворачивают хвост в «Остальные (n)» по исходным
  строкам, как требует §5.

Помощник по данным World Bank: `from wb import load, rows` — сам отбрасывает
44 макроагрегата (`World`, `Euro area`, `OECD members`…) по официальным кодам
и добавляет регион. Это уже проверено на живых данных, не надо заново
соединять `wb_*.csv` с OWID.

Темы: `--theme almanac|console|coral|furrow` (светлая и тёмная внутри).

Пиши движок вручную только если нужен тип графика, которого в kit нет
(карта, heatmap, сложный scatter). Тогда скопируй `engine.js` и
`template.html` в `$TASK` и добавь свой тип — остальные правила останутся
выполненными.

### 10.10. Чтение `/opt`, `/etc` и путь к Skill.MD

`/work` — корень рабочей папки, поэтому инструмент чтения файлов на `/opt` и
`/etc` отвечает `external_directory`. Это не поломка стенда, а граница
песочницы. Читай так:

```sh
cat /opt/viz/kit/README.md
sed -n '1,120p' /opt/hallmark/SANDBOX-NOTE.md
cat /etc/opencode/skills/economist-sandbox/SKILL.md
```

Полный текст этого Skill.MD для встраивания по §7 бери ровно отсюда:
`/etc/opencode/skills/economist-sandbox/SKILL.md`. Не ищи его через
`find / -name SKILL.md` — это долго и даёт ложные пути. В конструкторе текст
встраивается автоматически, передавать `--skill` не нужно.

### 10.11. Chart.js и headless-браузер

Если всё-таки используешь `/opt/viz/chart.umd.min.js`, обязательно:

- `animation: false` в опциях графика;
- контейнер `position: relative` с фиксированной `height` (например 280px),
  а не `flex: 1` без высоты;
- иначе `responsive: true` уходит в бесконечный цикл `ResizeObserver`, и
  `check_page.py` висит до таймаута («рендерер уничтожен»).

В конструкторе графики нарисованы обычным SVG — этой проблемы там нет.

### 10.12. Экономия шагов

- Уточнения студенту задавай **одним** вызовом инструмента `question`: и фокус
  задачи, и тему оформления (2–3 варианта из kit) сразу в одном массиве
  `questions`. Не растягивай анкету на два-три сообщения.
- Не пиши собственные скрипты проверки страницы и не гоняй браузер больше
  двух раз: `check_page.py` и `kit/verify_page.py` покрывают §9.
- Не обходи `/work/data` через копии и не создавай «новые» датасеты — читай
  по полному пути.

### 10.13. Финальный ответ студенту (обязательный формат)

Когда страница проверена, ответ короткий: **ссылка → краткий отчёт → что
сделать студенту**. Не пересказывай, что было сделано, не прикладывай код,
не перечисляй шаги отладки, не повторяй текст Skill.MD и не вставляй длинные
таблицы — всё это уже есть в самой странице.

1. **Ссылка** на готовую страницу (§10.2), первым блоком:

   ```
   https://<адрес стенда>/files/sessions/<id>/output/<файл>.html
   ```

2. **Краткий отчёт** — 3–5 строк: какой вопрос отвечает страница, какие KPI и
   графики на ней, сколько строк/стран/категорий в расчёте, что оговорено или
   исключено (агрегаты World Bank, пропуски, «последний доступный год»,
   несопоставимые единицы).

3. **Что осталось сделать студенту** — этот чек-лист дословно:

   ```
   Что сделать, чтобы сдать работу:
   ① В «Общие» замените название отчёта на свою фамилию или номер зачётки.
   ② В «Графики» скройте один график: отключите «Показывать график».
   ③ У другого, оставшегося видимым графика включите «Собственный цвет»
      и выберите новый цвет.
   ④ Скачайте Skill.MD внизу страницы.
   ```

Если задача была не учебной (студент просил конкретный отчёт для себя),
пункт 3 замени на его следующие шаги, но структура ответа та же: ссылка,
короткий отчёт, что делать дальше.
