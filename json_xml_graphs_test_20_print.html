Дополнительный блок по JSON и XML и выбору типа графика. Все ситуации описаны словами: картинки не нужны, чтобы понять задачу и выбрать форму. Только текстовые вопросы.

01JSON · СТРУКТУРА

Один заказ и список товаров

Нужно описать один заказ: id, дата и список из двух товаров. Какой фрагмент JSON соответствует этой структуре?

  1. A[{"id": 1042, "date": "2026-09-29"}, {"товар": "чай"}, {"товар": "мёд"}]
  2. B{"id": 1042, "date": "2026-09-29", "items": [{"товар": "чай", "qty": 2}, {"товар": "мёд", "qty": 1}]}
  3. C{"id": 1042, "date": "2026-09-29", "items": "чай, мёд"}
  4. D{"id": 1042, "date": "2026-09-29", "items": {"товар": "чай", "товар": "мёд"}}
02JSON · СИНТАКСИС

Запятая после последнего поля

Студент поправил JSON вручную: после последнего поля осталась запятая. Строгий парсер выдаёт ошибку. Почему?

  1. AJSON разрешает запятые только внутри массивов.
  2. BЗапятая допустима, если файл сохранён в UTF-8.
  3. CОшибка из-за того, что числа записаны без кавычек.
  4. DВ строгом JSON после последнего элемента запятая не допускается — это уже невалидный JSON.
03JSON · ТИПЫ

null, ноль и отсутствие поля

В API у части заказов discount = null, у части поля discount нет. Студент фильтрует discount < 100 и теряет такие строки. В чём причина?

  1. Anull и отсутствие ключа не дают истинного результата при сравнении с числом; их нужно обрабатывать отдельно — например, задать значение по умолчанию.
  2. Bnull и отсутствие поля — одно и то же, фильтр должен работать.
  3. CПроблема в кодировке: UTF-8 не поддерживает null.
  4. DНужно заменить null на строку "0", тогда сравнение точно сработает.
04JSON · ВАЛИДАЦИЯ

Схема проверяет не только наличие

JSON Schema требует, чтобы qty было целым числом не меньше 1. В данных встретились qty = "2" (строка) и qty = 0. Что покажет валидация?

  1. AОбе записи пройдут: "2" и 0 — числа.
  2. BТолько "2" пройдёт, потому что 0 — допустимое число.
  3. CОбе записи не пройдут: строка вместо целого и значение ниже минимума.
  4. DВалидация проверит только наличие поля qty, но не его тип и значение.
05JSON · КАЧЕСТВО

Два одинаковых ключа

В JSON дважды указан ключ id: сначала 1007, потом 1008. Чем это опасно?

  1. AЭто всегда синтаксическая ошибка, и файл не прочитается.
  2. BРазные парсеры могут оставить первое или последнее значение; результат зависит от реализации, поэтому дубли ключей недопустимы.
  3. CJSON автоматически суммирует значения одинаковых ключей.
  4. DВторой ключ автоматически превращается в массив.
06XML · СТРУКТУРА

Сколько корней у XML

В XML-файле два корневых элемента: orders и customers. Парсер сообщает об ошибке. Почему?

  1. AXML требует ровно два корневых элемента.
  2. BОшибка из-за отсутствия XSD-схемы.
  3. CНужно переименовать корневые элементы в атрибуты.
  4. DУ XML должен быть один корневой элемент; orders и customers нужно объединить в общий контейнер.
07XML · АТРИБУТЫ

Атрибут или дочерний элемент

В XML заказа id и status записаны как атрибуты, а date, amount и paid — как элементы. При разборе в таблицу что важно учесть?

  1. AАтрибуты и элементы — разные места данных: id и status нужно явно извлечь в столбцы, иначе они могут потеряться.
  2. BАтрибуты и элементы всегда автоматически попадают в одну колонку.
  3. CXML не поддерживает атрибуты, это ошибка.
  4. DАтрибуты автоматически становятся отдельными строками таблицы.
08XML · ДОПУСТИМОСТЬ

Амперсанд в названии

В XML название компании — Ivan & Sons. Парсер падает на символе &. Что сделать?

  1. AУдалить амперсанд из названия.
  2. BЗакодировать файл в UTF-16.
  3. CЭкранировать амперсанд символьной сущностью (amp) или обернуть текст в CDATA.
  4. DПоставить пробелы вокруг амперсанда.
09XML · ТАБЛИЦА

Четыре товара в одном заказе

В одном заказе четыре элемента item, у каждого есть sku и qty. Нужна плоская таблица «одна строка — товар заказа». Сколько строк будет для одного заказа и что произойдёт с полями заказа?

  1. AОдна строка; все товары нужно упаковать в одну ячейку.
  2. BЧетыре строки; поля заказа (id, дата, статус) повторятся в каждой строке.
  3. CЧетыре столбца; по одному столбцу на товар.
  4. DДве строки: одна для заказа, одна для списка товаров.
10XML · XSD

Дата и сумма не той формы

XSD требует типы xs:date и xs:decimal. В XML дата записана как 09/10/2026, сумма — как 1,250.50. Валидация не проходит. Почему?

  1. AXSD не поддерживает даты и десятичные числа.
  2. BДостаточно указать локаль ru-RU, и валидация пройдёт.
  3. CXSD проверяет только структуру, а значения не проверяет.
  4. DНужны форматы, предусмотренные типом: дата ГГГГ-ММ-ДД и десятичная точка без разделителя тысяч; иначе значение не соответствует xs:date и xs:decimal.

Точные значения до рубля

Финансовому отделу нужно найти точную выручку каждого из пяти филиалов до рубля и передать числа в отчёт. Что уместнее?

  1. AКруговая диаграмма с пятью секторами.
  2. BЛинейный график по филиалам.
  3. CТаблица со значениями.
  4. DТрёхмерная столбчатая диаграмма.
12ГРАФИК · НАКОПЛЕНИЕ

Итог и состав по годам

Нужно показать общую выручку за 2024, 2025 и 2026 годы и одновременно вклад трёх каналов в каждом году. Какой график уместнее?

  1. AСтолбчатая диаграмма с накоплением: столбец на год, сегменты — каналы.
  2. BКруговая диаграмма по годам.
  3. CТочечная диаграмма «год — выручка».
  4. DЛинейный график только общей выручки.
13ГРАФИК · ДОЛИ

Доли меняются, итог растёт

Нужно показать, как менялась доля четырёх каналов в выручке за три года, хотя общая выручка тоже росла. Что выбрать, чтобы сравнение долей не искажалось ростом общего итога?

  1. AОбычные столбцы с абсолютной выручкой.
  2. BЛинейный график общей выручки.
  3. CКруговую диаграмму за каждый год без подписей.
  4. D100% столбчатую диаграмму с накоплением: каждый год — 100%, сегменты — доли каналов.

День недели и час пик

Есть число заказов по дням недели и часам: 7 дней × 12 интервалов. Нужно быстро найти самые загруженные сочетания «день + час». Что выбрать?

  1. A84 отдельных столбца.
  2. BТепловую карту: дни по одной оси, часы по другой, цвет — число заказов.

  4. DЛинейный график по всем 84 значениям.
15ГРАФИК · КАРТА

Где больше клиентов

  1. AКруговую диаграмму регионов.
  2. BЛинейный график по регионам.
  3. CКарту с интенсивностью цвета по числу клиентов.
  4. DГистограмму числа клиентов.
16ГРАФИК · ДВЕ ОСИ

Рубли и проценты на одном полотне

На одном графике хотят показать выручку в рублях и конверсию в процентах, каждую со своей осью Y. Почему это рискованно и что сделать?

  1. AДве оси создают произвольное впечатление связи; лучше два отдельных графика или индексированные значения с явным пояснением.
  2. BДве оси всегда точнее одной, поэтому график можно оставить.
  3. CНужно перевести рубли в проценты и сложить показатели.
  4. DДостаточно сделать обе оси одного цвета.
17ГРАФИК · МНОГО РЯДОВ

Двенадцать линий на одном графике

На одном линейном графике 12 товарных линий. Читатель не может проследить ни одну из них. Что сделать?

  1. AСделать все линии ярче и добавить 12 оттенков.
  2. BДобавить третью ось Y.
  3. CПерейти на круговую диаграмму с 12 секторами.
  4. DВыделить 2–3 ключевые линии, остальные показать серым, или разложить ряды на малые кратные графики.

  1. AЛинейный график по каналам.
  2. BКруговая диаграмма с четырьмя секторами.

19ГРАФИК · РАЗЛИЧИЕ

Столбцы или гистограмма

Чем столбчатая диаграмма отличается от гистограммы?

  1. AНичем: это два названия одного графика.
  2. BСтолбчатая — только для времени, гистограмма — только для денег.
  3. CСтолбчатая сравнивает категории, а гистограмма показывает распределение одной числовой величины по интервалам.
  4. DГистограмма всегда использует круговые сектора.
20ГРАФИК · ОШИБКА

Линия между независимыми каналами

Аналитик соединил линией пять каналов продаж, расположенных по алфавиту, и подписал: «динамика каналов». Почему такой график может вводить в заблуждение?

  1. AЛиния создаёт впечатление последовательности и изменения во времени, хотя каналы — независимые категории; уместнее столбцы.
  2. BЛиния всегда запрещена для пяти значений.
  3. CКаналы нельзя сравнивать между собой.
  4. DНужно просто добавить больше точек на линию.
