# Дополнительный блок: JSON, XML и типы графиков
**Курс:** «Визуализация данных с использованием инструментов ИИ» · РУДН  
**Темы:** JSON, XML, XSD, выбор типа графика  
**Формат:** 20 вопросов, 4 варианта ответа, один правильный. Изображений нет.  
**Время:** 30 минут · **Максимум:** 20 баллов  

> Правильные ответы и распределение по темам — в конце документа, после ключа.

## Инструкция
1. В каждом вопросе выберите один правильный ответ.
2. За правильный ответ — 1 балл, за неправильный — 0.
3. Пользоваться конспектами и ИИ-сервисами нельзя.
4. Если вопрос кажется неоднозначным, выбирайте ответ, наиболее близкий к формулировкам лекции.

### 1. Один заказ и список товаров

*JSON · СТРУКТУРА*

Нужно описать один заказ: id, дата и список из двух товаров. Какой фрагмент JSON соответствует этой структуре?

- **A)** [{"id": 1042, "date": "2026-09-29"}, {"товар": "чай"}, {"товар": "мёд"}]
- **B)** {"id": 1042, "date": "2026-09-29", "items": [{"товар": "чай", "qty": 2}, {"товар": "мёд", "qty": 1}]}
- **C)** {"id": 1042, "date": "2026-09-29", "items": "чай, мёд"}
- **D)** {"id": 1042, "date": "2026-09-29", "items": {"товар": "чай", "товар": "мёд"}}


### 2. Запятая после последнего поля

*JSON · СИНТАКСИС*

Студент поправил JSON вручную: после последнего поля осталась запятая. Строгий парсер выдаёт ошибку. Почему?

- **A)** JSON разрешает запятые только внутри массивов.
- **B)** Запятая допустима, если файл сохранён в UTF-8.
- **C)** Ошибка из-за того, что числа записаны без кавычек.
- **D)** В строгом JSON после последнего элемента запятая не допускается — это уже невалидный JSON.


### 3. null, ноль и отсутствие поля

*JSON · ТИПЫ*

В API у части заказов discount = null, у части поля discount нет. Студент фильтрует discount < 100 и теряет такие строки. В чём причина?

- **A)** null и отсутствие ключа не дают истинного результата при сравнении с числом; их нужно обрабатывать отдельно — например, задать значение по умолчанию.
- **B)** null и отсутствие поля — одно и то же, фильтр должен работать.
- **C)** Проблема в кодировке: UTF-8 не поддерживает null.
- **D)** Нужно заменить null на строку "0", тогда сравнение точно сработает.


### 4. Схема проверяет не только наличие

*JSON · ВАЛИДАЦИЯ*

JSON Schema требует, чтобы qty было целым числом не меньше 1. В данных встретились qty = "2" (строка) и qty = 0. Что покажет валидация?

- **A)** Обе записи пройдут: "2" и 0 — числа.
- **B)** Только "2" пройдёт, потому что 0 — допустимое число.
- **C)** Обе записи не пройдут: строка вместо целого и значение ниже минимума.
- **D)** Валидация проверит только наличие поля qty, но не его тип и значение.


### 5. Два одинаковых ключа

*JSON · КАЧЕСТВО*

В JSON дважды указан ключ id: сначала 1007, потом 1008. Чем это опасно?

- **A)** Это всегда синтаксическая ошибка, и файл не прочитается.
- **B)** Разные парсеры могут оставить первое или последнее значение; результат зависит от реализации, поэтому дубли ключей недопустимы.
- **C)** JSON автоматически суммирует значения одинаковых ключей.
- **D)** Второй ключ автоматически превращается в массив.


### 6. Сколько корней у XML

*XML · СТРУКТУРА*

В XML-файле два корневых элемента: orders и customers. Парсер сообщает об ошибке. Почему?

- **A)** XML требует ровно два корневых элемента.
- **B)** Ошибка из-за отсутствия XSD-схемы.
- **C)** Нужно переименовать корневые элементы в атрибуты.
- **D)** У XML должен быть один корневой элемент; orders и customers нужно объединить в общий контейнер.


### 7. Атрибут или дочерний элемент

*XML · АТРИБУТЫ*

В XML заказа id и status записаны как атрибуты, а date, amount и paid — как элементы. При разборе в таблицу что важно учесть?

- **A)** Атрибуты и элементы — разные места данных: id и status нужно явно извлечь в столбцы, иначе они могут потеряться.
- **B)** Атрибуты и элементы всегда автоматически попадают в одну колонку.
- **C)** XML не поддерживает атрибуты, это ошибка.
- **D)** Атрибуты автоматически становятся отдельными строками таблицы.


### 8. Амперсанд в названии

*XML · ДОПУСТИМОСТЬ*

В XML название компании — Ivan & Sons. Парсер падает на символе &. Что сделать?

- **A)** Удалить амперсанд из названия.
- **B)** Закодировать файл в UTF-16.
- **C)** Экранировать амперсанд символьной сущностью (amp) или обернуть текст в CDATA.
- **D)** Поставить пробелы вокруг амперсанда.


### 9. Четыре товара в одном заказе

*XML · ТАБЛИЦА*

В одном заказе четыре элемента item, у каждого есть sku и qty. Нужна плоская таблица «одна строка — товар заказа». Сколько строк будет для одного заказа и что произойдёт с полями заказа?

- **A)** Одна строка; все товары нужно упаковать в одну ячейку.
- **B)** Четыре строки; поля заказа (id, дата, статус) повторятся в каждой строке.
- **C)** Четыре столбца; по одному столбцу на товар.
- **D)** Две строки: одна для заказа, одна для списка товаров.


### 10. Дата и сумма не той формы

*XML · XSD*

XSD требует типы xs:date и xs:decimal. В XML дата записана как 09/10/2026, сумма — как 1,250.50. Валидация не проходит. Почему?

- **A)** XSD не поддерживает даты и десятичные числа.
- **B)** Достаточно указать локаль ru-RU, и валидация пройдёт.
- **C)** XSD проверяет только структуру, а значения не проверяет.
- **D)** Нужны форматы, предусмотренные типом: дата ГГГГ-ММ-ДД и десятичная точка без разделителя тысяч; иначе значение не соответствует xs:date и xs:decimal.


### 11. Точные значения до рубля

*ГРАФИК · ТАБЛИЦА*

Финансовому отделу нужно найти точную выручку каждого из пяти филиалов до рубля и передать числа в отчёт. Что уместнее?

- **A)** Круговая диаграмма с пятью секторами.
- **B)** Линейный график по филиалам.
- **C)** Таблица со значениями.
- **D)** Трёхмерная столбчатая диаграмма.


### 12. Итог и состав по годам

*ГРАФИК · НАКОПЛЕНИЕ*

Нужно показать общую выручку за 2024, 2025 и 2026 годы и одновременно вклад трёх каналов в каждом году. Какой график уместнее?

- **A)** Столбчатая диаграмма с накоплением: столбец на год, сегменты — каналы.
- **B)** Круговая диаграмма по годам.
- **C)** Точечная диаграмма «год — выручка».
- **D)** Линейный график только общей выручки.


### 13. Доли меняются, итог растёт

*ГРАФИК · ДОЛИ*

Нужно показать, как менялась доля четырёх каналов в выручке за три года, хотя общая выручка тоже росла. Что выбрать, чтобы сравнение долей не искажалось ростом общего итога?

- **A)** Обычные столбцы с абсолютной выручкой.
- **B)** Линейный график общей выручки.
- **C)** Круговую диаграмму за каждый год без подписей.
- **D)** 100% столбчатую диаграмму с накоплением: каждый год — 100%, сегменты — доли каналов.


### 14. День недели и час пик

*ГРАФИК · ТЕПЛОВАЯ КАРТА*

Есть число заказов по дням недели и часам: 7 дней × 12 интервалов. Нужно быстро найти самые загруженные сочетания «день + час». Что выбрать?

- **A)** 84 отдельных столбца.
- **B)** Тепловую карту: дни по одной оси, часы по другой, цвет — число заказов.
- **C)** Круговую диаграмму с 84 секторами.
- **D)** Линейный график по всем 84 значениям.


### 15. Где больше клиентов

*ГРАФИК · КАРТА*

Нужно показать, в каких регионах России у компании больше клиентов, и ответить на вопрос «где их больше всего». Что выбрать?

- **A)** Круговую диаграмму регионов.
- **B)** Линейный график по регионам.
- **C)** Карту с интенсивностью цвета по числу клиентов.
- **D)** Гистограмму числа клиентов.


### 16. Рубли и проценты на одном полотне

*ГРАФИК · ДВЕ ОСИ*

На одном графике хотят показать выручку в рублях и конверсию в процентах, каждую со своей осью Y. Почему это рискованно и что сделать?

- **A)** Две оси создают произвольное впечатление связи; лучше два отдельных графика или индексированные значения с явным пояснением.
- **B)** Две оси всегда точнее одной, поэтому график можно оставить.
- **C)** Нужно перевести рубли в проценты и сложить показатели.
- **D)** Достаточно сделать обе оси одного цвета.


### 17. Двенадцать линий на одном графике

*ГРАФИК · МНОГО РЯДОВ*

На одном линейном графике 12 товарных линий. Читатель не может проследить ни одну из них. Что сделать?

- **A)** Сделать все линии ярче и добавить 12 оттенков.
- **B)** Добавить третью ось Y.
- **C)** Перейти на круговую диаграмму с 12 секторами.
- **D)** Выделить 2–3 ключевые линии, остальные показать серым, или разложить ряды на малые кратные графики.


### 18. Четыре части одного целого

*ГРАФИК · КРУГ*

Нужно показать, какую долю в общей выручке даёт каждый из четырёх каналов. Каких-либо сравнений между годами нет. Что уместно?

- **A)** Линейный график по каналам.
- **B)** Круговая диаграмма с четырьмя секторами.
- **C)** Точечная диаграмма «канал — выручка».
- **D)** Гистограмма выручки по каналам.


### 19. Столбцы или гистограмма

*ГРАФИК · РАЗЛИЧИЕ*

Чем столбчатая диаграмма отличается от гистограммы?

- **A)** Ничем: это два названия одного графика.
- **B)** Столбчатая — только для времени, гистограмма — только для денег.
- **C)** Столбчатая сравнивает категории, а гистограмма показывает распределение одной числовой величины по интервалам.
- **D)** Гистограмма всегда использует круговые сектора.


### 20. Линия между независимыми каналами

*ГРАФИК · ОШИБКА*

Аналитик соединил линией пять каналов продаж, расположенных по алфавиту, и подписал: «динамика каналов». Почему такой график может вводить в заблуждение?

- **A)** Линия создаёт впечатление последовательности и изменения во времени, хотя каналы — независимые категории; уместнее столбцы.
- **B)** Линия всегда запрещена для пяти значений.
- **C)** Каналы нельзя сравнивать между собой.
- **D)** Нужно просто добавить больше точек на линию.
