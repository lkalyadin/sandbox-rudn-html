**Почему пришлось перевыпускать.** Сертификат выдаётся на IP в профиле `shortlived`
(срок ~6.7 суток), и продлевал его `opencode-student-cert.service` через
`docker run certbot/certbot` (скрипт `60-renew-cert.sh` студенческого стенда). Docker на
этом хосте `inactive + masked`, поэтому таймер падал каждую ночь, а 28.10 до истечения
оставались сутки. Ошибка в логе: `Cannot connect to the Docker daemon`.

**Как продлевается теперь (28.10.2026).** Хост — единственный владелец сертификата:

```
~/bin/oc-cert-renew.sh          # certbot 5.8 из ~/.local/venvs/certbot, без docker и root
~/.local/share/oc-cert          # свой ACME-аккаунт + lineage (live/, archive/)
/srv/.../edge/certs/*.pem       # раскладка: fullchain 644, privkey 600 (uid 1001)
oc-cert-renew.timer             # ежедневно 04:30 ±15 мин, Persistent=true
```

* проверка `HTTP-01` на порту 80 (`ip_unprivileged_port_start=80`), режим `standalone`;
  если 80 занят edge — `webroot` `edge/acme` (edge отдаёт `/.well-known/acme-challenge/`);
* продление при остатке < 3 суток → ~2 выпуска в неделю, лимиты LE (5 одинаковых
  сертификатов/неделю) не задеваются, до истечения остаётся минимум 2 попытки;
* после раскладки — `systemctl --user reload caddy`, а если Caddy не перечитал файлы
  (он их кэширует при неизменном конфиге) — рестарт, затем сверка отдаваемого
  сертификата по отпечатку;
* запуск вручную: `bash ~/bin/oc-cert-renew.sh` (продлит, если пора), `--force`,
  `--test` (staging LE, без раскладки), `--check` (только отчёт — выпущено / лежит /
  отдаётся); логи: `journalctl --user -u oc-cert-renew`.

Скрипт `60-renew-cert.sh` студенческого стенда и его юнит **не тронуты**, но таймер
`opencode-student-cert.timer` выключен: два продления одного IP — это лишние выпуски и
риск лимитов. Когда студенческий стенд вернётся, его certbot должен использовать эти же
файлы `edge/certs`, а не продлевать свой lineage.
